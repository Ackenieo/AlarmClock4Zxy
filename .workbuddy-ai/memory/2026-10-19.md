# 2026-10-19

## 开合跳闹钟（Android / Java）从零实现

在空模板工程 `D:/WWWWokP/AlarmClock4jACW` 上完成了完整应用（Java，minSdk 26，targetSdk 37，AGP 9.4.1）。

**架构**
- `AlarmManager.setAlarmClock` → `AlarmReceiver` → `AlarmService`（前台服务 mediaPlayback，MediaPlayer + Vibrator + fullScreenIntent 通知）→ `RingingActivity`（锁屏全屏）→ `ExerciseActivity`（CameraX + ML Kit Pose，达标 RESULT_OK 才停）。
- 数据用 SharedPreferences + JSON（`AlarmStore`），未引入数据库。
- `JumpingJackCounter` 设计成纯逻辑、只吃 `Landmarks`（33 点归一化坐标），因此可以 JVM 单测。

**两个关键坑（以后遇到同类问题直接复用结论）**
1. ML Kit `PoseLandmark.getPosition()` 返回的是**图像像素坐标**，不是 0~1 归一化。必须按图像尺寸归一化，否则骨架画到屏幕外、`torso > 0.5` 之类的绝对阈值全部失效。已封装 `Landmarks.fromPose()` 并做坐标空间自检。
2. 开合跳计数**不能做 EMA 平滑**：峰值只持续 3~5 帧，EMA 滞后会把手臂得分从 0.9 削到 0.56，75s 测试视频从 56 个掉到 10 个。改用时间滞回（hold 100ms / min open 180ms / min gap 320ms）。
3. 状态机里 `pending` 必须在 `candidate == phase` 时清空，否则两次孤立闪现会拼成一次计数（被单测抓到）。

**阈值标定方法**（可复用）：`tools/verify_counter.py` 用 MediaPipe BlazePose（与 ML Kit 同源 33 点）离线跑测试视频，导出每帧 arm/leg 得分，用与 Java 相同的状态机做参数扫描。最终取 0.55/0.90（平台区稳定，56 次）。

**验证结论**
- 单元测试 8 个全绿。
- 视频测试（App 内 ML Kit 逐帧）计数与离线一致；骨架与画面贴合。
- 模拟器 MyPhone（API 37）实测：后台/息屏状态闹钟能通过 fullScreenIntent 拉起全屏响铃页；运动完成 → 服务停止、通知清除。
- Android 14+ 的 `USE_FULL_SCREEN_INTENT` 默认被拒（appops rejectTime），已在 MainActivity 做引导跳转 `ACTION_MANAGE_APP_USE_FULL_SCREEN_INTENT`。

**环境备忘**
- SDK: `D:\Android\Sdk`；AVD home: `D:\Android\Sdk\adv-device`，可用 AVD 是 `MyPhone`（不是 `test_device`，后者在 `~/.android/avd` 且 ANDROID_AVD_HOME 指向别处）。
- 无 ffmpeg；视频抽帧用 `pip install opencv-python-headless`；离线骨骼用 mediapipe 1.1.1（新 API 只有 `mediapipe.tasks`，无 `solutions`）。
- adb 长按用 `input swipe x y x y 900`；坐标要用 `uiautomator dump` 的真实 bounds，截图缩放会估偏。
